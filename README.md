# Ruhamaa | رحماء

منصة مجتمعية في مدينة مأرب تربط الأشياء والوقت والمهارات غير المستغلة باحتياجات حقيقية، مع الحفاظ على الكرامة والخصوصية وفصل الأطراف قدر الإمكان عبر تشغيل رحماء.

## Android identity

- Application ID: `com.ruhamaa.app`
- Production domain: `https://ruhamaa.com`
- Local/internal OAuth callback: `com.ruhamaa.app://login-callback`
- Production App Link callback after verification: `https://ruhamaa.com/login-callback`

## V1 Scope

- تسجيل الدخول بحساب Google للمستخدمين المجتمعيين.
- حساب واحد يمكنه تسجيل احتياج، تقديم شيء، أو تقديم وقت ومهارة.
- تبرعات أشياء مع صور خاصة ومطابقة Need-first.
- عروض وقت ومهارات مجانية أو عمل مجاني مع مواد حسب الحالة.
- لا توجد سوق عامة، ولا تصفح لمقدمي الخدمات أو المستفيدين.
- المطابقة تمر بمراجعة رحماء وموافقة الأطراف.
- Workflow للموصلين مع PIN للاستلام والتسليم للأشياء.
- مساهمات تشغيلية اختيارية مرتبطة بعمليات التوصيل.
- Risk Flags ومراجعة يدوية للحالات المشبوهة.
- لوحة إدارة وتشغيل ضمن نفس قاعدة البيانات.

## Time & Skills

رحماء لا يقسم المجتمع إلى «متبرعين» و«محتاجين» كهوية ثابتة. الشخص نفسه قد يحتاج شيئًا أو خدمة وفي الوقت نفسه يستطيع تقديم شيء آخر أو ساعات من وقته أو مهارته.

- تقديم العطاء أو الساعات لا يمنح أولوية في الاستحقاق.
- الحصول على مساعدة لا يتطلب تقديم مقابل.
- لا توجد نقاط أو رصيد ساعات أو مقايضة أو عملة داخلية.
- عروض الخدمات تُراجع قبل تفعيلها.
- مطابقة الخدمة لا تُعتمد إلا بعد موافقة مقدم الخدمة وصاحب الاحتياج.
- الخدمات الحضورية تكشف فقط المعلومات الضرورية بعد الموافقة والتنسيق.

راجع `docs/RUHAMA_TIME_AND_SKILLS.md` للتفاصيل.

## Core principles

1. الاحتياج أولًا، ولا توجد واجهة Marketplace.
2. المتبرع والمستفيد في تبرعات الأشياء لا يعرف أحدهما هوية الآخر.
3. في الخدمات الحضورية يظهر فقط الحد الأدنى الضروري من المعلومات بعد موافقة الطرفين.
4. Google Auth للمصادقة، وليس كإثبات هوية نهائي.
5. المساهمات التشغيلية اختيارية ولا تعطي أولوية في الاستحقاق.
6. تقديم وقت أو مهارة لا يعطي نقاطًا أو أفضلية ولا يخلق دينًا متبادلًا.
7. القرارات الحساسة أو عالية الخطورة تمر بمراجعة بشرية.
8. أقل قدر ضروري من البيانات يظهر أثناء تنفيذ المهمة.
