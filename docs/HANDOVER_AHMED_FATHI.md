# ابدأ هنا يا أحمد فتحي — تسليم تطبيق رحماء

تاريخ تثبيت الحالة: 10 سبتمبر 2026. هذه نقطة تسليم لأحمد لاستكمال المشروع وتجهيزه للنشر في Google Play بتكليف مالك المشروع. لم يُتحقق من قبول دعوة GitHub أو وصول أحمد للخدمات الأخرى. البريد الذي زوده المالك لا يُنشر في هذا المستودع العام.

## القرار الحالي

**PASS للاختبارات المحددة على النسخة أدناه، وHOLD للإطلاق العام.** التطبيق ليس منشورًا في Google Play وفق الأدلة المتاحة؛ لا يوجد دليل تسليم AAB إنتاجي موقّع أو قبول مراجعة المتجر. نجاح CI ليس إثبات تغطية كل حقل أو كل جهاز.

اقرأ هذه الوثيقة أولًا، ثم تقرير [إغلاق عيوب الاختبارات](handover-evidence/SECURITY_CLOSURE_2026-09-10.md). الوثائق القديمة تمثل مراحلها؛ حالة GitHub وسجل Supabase الحاليان مقدمان عند التعارض. أعد تثبيت الحالة عند بدء العمل إذا مضى وقت على هذا التسليم.

## 1. ما هو المشروع وما الموجود

رحماء منصة مجتمعية للأشياء والوقت والمهارات في مأرب. الحساب الشخصي يستطيع التبرع وتسجيل احتياج وعرض خدمة أو طلبها. الأدوار التشغيلية تشمل الإدارة والمشرف والموصل؛ الشريك التجاري ملف مستقل يحتاج اعتمادًا.

- تسجيل Google عبر Supabase، حساب وعناوين وموقع، وحسابات فريق مع تغيير كلمة المرور المؤقتة.
- تبرعات واحتياجات بتصنيف V2 وخصائص دقيقة، ومراجعة ومطابقة بشرية وعرض خاص لصاحب الاحتياج لقبوله أو رفضه.
- بطاقات احتياج راجعها الفريق، محايدة ومحجوبة الهوية؛ الاستجابة لا تضمن اختيار صاحب البطاقة.
- خدمات وقت ومهارة، موافقات وجدولة وإكمال، وشركاء وسعة وبلاغات سلامة.
- مساهمات تشغيلية نقدية اختيارية مع اعتماد إداري؛ ليست نظام دفع إلكتروني أو وسيلة أولوية للاستحقاق.
- تأهيل ومخزون: استلام وفحص A–D، تنظيف وإصلاح وجاهزية توزيع أو إعادة تدوير موثقة.
- مركز متابعة وتنبيهات داخل التطبيق، إدارة للمخاطر والأدوار والمناطق والتقارير.
- Courier V2: إسناد → قبول/اعتذار → استلام برمز → بدء التسليم → تسليم برمز؛ تعثر وإعادة إسناد وتدقيق وتحديث Realtime. بيانات الاتصال تظهر تدريجيًا للحاجة التشغيلية.
- الموقع العام وصفحات الخصوصية والشروط وطلب حذف الحساب موجودة في `site/`. وجود الملفات لا يثبت صلاحية الروابط المنشورة أو اكتمال تنفيذ الحذف الفعلي.

لا يوجد سوق مفتوح للتبرعات أو دردشة مباشرة بين المتبرع والمستفيد. لا تغيّر قواعد الخصوصية أو الأولوية أو الاسم التجاري من تلقاء نفسك؛ ثبت أي قرار منتج جديد مع المالك. Push أثناء إغلاق التطبيق لم يكتمل.

## 5. أول يوم عمل: الوصول والتشغيل

| الوصول المطلوب | ما يجب تأكيده مع المالك |
|---|---|
| GitHub | قبول الدعوة وقراءة/كتابة الفروع وActions؛ لا نفترض أن البريد هو اسم مستخدم GitHub |
| Supabase | دعوة المشروع المناسبة، staging، Auth والإعدادات والـEdge Functions والنسخ الاحتياطي |
| Google Cloud / OAuth | ملكية المشروع وOAuth consent والعملاء وبصمات الشهادات |
| Firebase / FCM | إنشاء/تسليم المشروع وصلاحية الإرسال الخادمية إذا نُفذ Push |
| Google Play Console | حساب المطور المناسب ودعوة بصلاحيات التطبيق والإصدارات، واستكمال تحقق الحساب |
| النطاق والاستضافة | DNS وGitHub Pages أو الاستضافة الفعلية، وروابط السياسات وApp Links |
| التوقيع | وجود upload key من عدمه، حيازته ونسخته الاحتياطية؛ لا تُنشئ بديلًا لمفتاح قائم دون خطة |

لا ترسل keystore أو service_role أو كلمات مرور عبر المستودع أو التذاكر. مفاتيح العميل المسموح بها وحدها تدخل التطبيق؛ GitHub access لا يمنح صلاحيات بقية الخدمات.

ابدأ من checkout مستقل، وسجل SHA قبل أي تعديل:

```powershell
git clone https://github.com/msorori-mh/Rohamaa.git
cd Rohamaa
git fetch origin
git switch -c ahmed/release-preparation origin/codex/isolated-e2e-tests
git rev-parse HEAD
cd app
flutter --version
flutter pub get
flutter analyze
flutter test test
```

للتشغيل التفاعلي أدخل إعدادات البيئة التي سلمها المالك (يفضل staging للتجارب):

```powershell
$RuhamaaUrl = Read-Host "Supabase URL"
$RuhamaaPublicKey = Read-Host "Supabase publishable key"
flutter run "--dart-define=SUPABASE_URL=$RuhamaaUrl" "--dart-define=SUPABASE_ANON_KEY=$RuhamaaPublicKey"
```

اسم المتغير في الكود SUPABASE_ANON_KEY حتى عند استخدام publishable key. غياب الإعدادات ينتج رسالة النسخة غير مكتملة الإعداد. نجاح APK في CI العادي لا يعني أنه قابل للتجربة المتصلة؛ لا توزع artifacts اختبار localhost.

## 7. فجوات بناء Google Play التي يجب إصلاحها أولًا

**فجوة مؤكدة في الكود الحالي:** `.github/workflows/android_release_bundle.yml` يبني AAB مع مفاتيح التوقيع لكنه لا يمرر `SUPABASE_URL` و`SUPABASE_ANON_KEY`. دليل `ANDROID_RELEASE.md` القديم يعرض بناءً محليًا دون هذه القيم أيضًا. أصلح المسارين مع فشل مبكر عند غياب الإعدادات واختبار بدء النسخة الموقعة. لا يكفي أن ينجح التوقيع.

أسرار التوقيع التي يطلبها المسار الحالي: `ANDROID_KEYSTORE_BASE64`، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`، `ANDROID_KEY_PASSWORD`. لم يُتحقق من وجود قيمها أو وجود حساب Play في هذه الجولة؛ وجود workflow ليس دليل إعدادها.

افصل upload certificate عن Play App Signing certificate. بعد أول رفع اختباري، اضبط بصمة App Signing في assetlinks.json وOAuth، وتحقق من الروابط المنشورة والسماح بالـredirect قبل تحويل مسار الدخول الإنتاجي. الملف `site/.well-known/assetlinks.json.template` قالب فقط.

وقت إعداد هذا التسليم، [متطلبات Target API الرسمية](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en-GB) تنص على API 36 للتطبيقات الجديدة والتحديثات. أعد التحقق عند الرفع، وافحص القيمة الناتجة فعليًا في AAB؛ تشغيل المحاكي API 35 لا يثبت targetSdk. تحقق كذلك من متطلبات المكتبات الأصلية وتقرير Play pre-launch.

إذا انطبقت متطلبات الحسابات الشخصية الجديدة، [دليل Google الرسمي](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en) يطلب اختبارًا مغلقًا بـ12 مختبرًا مشتركًا لمدة 14 يومًا متواصلة قبل طلب الوصول للإنتاج. نوع الحساب وتاريخه غير معروفين هنا؛ لا تفترض أن Internal testing يغني عن هذه البوابة.

راجع `docs/PLAY_DATA_SAFETY.md` مقابل السلوك الفعلي والـSDKs بعد إضافة FCM؛ لا تنسخ التصريحات قبل المطابقة. أكد اسم التطبيق النهائي مع المالك قبل إنشاء مواد المتجر، مع الحفاظ على package ID القائم ما لم توجد خطة معتمدة لتغييره.

## 8. خريطة الملفات

- `app/lib/main.dart` و`app/lib/src/app.dart`: بدء التطبيق والجلسة والموجه.
- `app/lib/src/features/`: شاشات المستخدم والإدارة والموصل والخدمات والشركاء والمخزون.
- `app/lib/src/data/`: مستودعات استدعاء Supabase، و`domain/` لقواعد العرض والتشغيل.
- `supabase/migrations/`: المخطط والسياسات وRPCs؛ `supabase/functions/`: إنشاء الموظف وتغيير كلمة مروره.
- `tests/e2e/` و`app/integration_test/live_app_test.dart` في فرع #11: الاختبارات المعزولة.
- `.github/workflows/isolated_e2e.yml`: بوابة الاختبارات؛ `flutter_ci.yml`: CI المعتاد؛ `android_release_bundle.yml`: مسار التوقيع اليدوي الناقص إعداد العميل.
- `docs/ANDROID_RELEASE.md`، `docs/GOOGLE_PLAY_RELEASE.md`، `docs/PLAY_DATA_SAFETY.md`: مراجع إصدار تُحدّث مع التنفيذ.
- `docs/UAT_CATEGORY_V2_PARTNERS.md`، `docs/UAT_OPERATIONS_CENTER.md`، `docs/UAT_ITEM_RECOVERY_INVENTORY.md`: قوائم قبول تفصيلية.
- `docs/architecture.md`، `docs/state-machines.md`، `docs/IMPLEMENTATION_STATUS.md`: مراجع معمارية/تاريخية؛ قارنها بالكود الأحدث.
