# عطاء — Ataa: الهوية المعتمدة

اعتمد المالك اسم **عطاء** بدل الاسم السابق في سبتمبر 2026. الكتابة اللاتينية المستخدمة في الواجهة والمواد الجديدة: **Ataa**. عبارة الهوية: **لكلٍّ منّا ما يقدّمه**. يعبر الرمز عن شخصين متساويين في الحجم والمستوى، يشاركان في دائرة واحدة؛ يمكن للشخص تقديم شيء أو وقت أو مهارة وطلب ما يحتاجه من الحساب نفسه.

## ما يتغير

- اسم Android الظاهر وأيقونة المشغّل، أسماء التطبيق والعناوين ورسائل البدء والدخول والمقدمة والأدوار والخدمات والخصوصية.
- رسم الهوية في Flutter وشعار الموقع وfavicon وأيقونة متجر 512×512، مع استمرار الأخضر والذهبي والخط العربي المحلي.
- جميع صفحات الموقع ونصوص SEO والشروط والخصوصية والتواصل والحذف؛ رابط سيستراك SYSTRAC.TECH محفوظ.
- أسماء ملفات APK/AAB المعروضة في Actions ووثائق الإصدار الحالية.
- ثلاثة قوالب/رسائل خادمية في دوال محددة فقط بترحيل أمامي؛ الإشعارات القديمة المخزنة لا يعاد كتابتها، ويعرض التطبيق القالبين القديمين المطابقين فقط باسم عطاء. محتوى المستخدم وسجلات التدقيق لا يتغيران.

## حدود التوافق المقصودة

| المعرّف | القيمة المستمرة | السبب |
|---|---|---|
| Android applicationId/namespace | `com.ruhamaa.app` | حفظ هوية التحديث والتوقيع وتجنب إنشاء تطبيق آخر |
| OAuth custom scheme | `com.ruhamaa.app://login-callback` | حفظ تسجيل الدخول في النسخ الحالية |
| الموقع والبريد | `ruhamaa.com` وsupport/ privacy على النطاق نفسه | لا يوجد نطاق بديل مملوك ومهيأ مُثبت |
| GitHub | `msorori-mh/Rohamaa` | حفظ الاستنساخ والصلاحيات والتكاملات وتسليم أحمد |
| Supabase | `vclicpejajxadsbuakdw` | لا نقل أو إنشاء مشروع أو تغيير مستخدمين وبيانات |
| Dart package/classes/preferences | `ruhamaa` وأسماء الفئات والمفاتيح الداخلية الحالية | لا أثر مرئي للمستخدم؛ حفظ imports والجلسات وحالة المقدمة |
| الترحيلات والتقارير القديمة | أسماء ومحتويات التاريخ الأصلية | حفظ أدلة الاختبارات وسجل التطبيق؛ لا نزوّر التاريخ باستبدال شامل |

هذه استثناءات تقنية موثقة وليست أجزاء مرئية نُسيت. لا تغيّر package ID أو OAuth أو البريد بعملية بحث واستبدال عامة. شراء/نقل نطاق جديد وتغيير اسم المستودع يحتاج خطة روابط وDNS وبريد وإعادة توجيه متكاملة.

## الفروع المفتوحة وتسليم أحمد

PR #9 و#10 و#11 تبقى طلبات أعمال سابقة غير مدمجة؛ تغيير الهوية لا يصرح بدمج وظائفها أو تطبيق ترحيل الأمان الخاص بها. بعد دمج أي فرع قديم:

1. حل التعارضات بالاحتفاظ بالسلوك الجديد وبالاسم عطاء؛ لا تستبدل ملف واجهة كاملًا بنسخة أقدم.
2. شغّل `python3 tools/branding/apply_identity.py` من checkout يحتوي أدوات الهوية الجديدة. الأداة تحدث الاسم الظاهر فقط، ولا تنقل النطاق أو المخطط.
3. أبق رسم `_RuhamaaBrandPainter` الجديد و`ataa_launcher.xml`؛ اسم الفئة القديم داخلي فقط.
4. شغّل `python3 tools/branding/check_identity.py` وFlutter analyze/tests وبوابة E2E للفرع المدمج. حدّث توقعات النصوص العربية في integration_test إلى عطاء.
5. لا تطبق الترحيلات التاريخية مجددًا؛ طابق سجل الإنتاج. ترحيل `ataa_display_identity` مستقل عن `e2e_security_closure`.

## إعدادات خارج المستودع

لا توجد في الأدوات الحالية صلاحية إدارة اسم Google OAuth consent أو قائمة Google Play. على مسؤول تلك الحسابات تحديث **اسم العرض والشعار** إلى عطاء/Ataa، دون تغيير client IDs أو الشهادات أو redirect allow-list. إن كانت قوالب بريد Auth مخصصة أو اسم مرسل البريد تحمل الاسم السابق، حدّث اسم العرض والنصوص مع بقاء نطاق المرسل الموثق. لا ندّعي تنفيذ هذه الخطوات أو النشر في Google Play دون دليل وصول وتنفيذ.

قبل إنتاج النسخة العامة، أكمل حقن إعدادات Supabase في مسار AAB الذي وثقته عملية التسليم، وجهّز التوقيع. نجاح debug APK يثبت البناء، ولا يجعله نسخة عامة جاهزة إذا كان بلا إعدادات العميل.
